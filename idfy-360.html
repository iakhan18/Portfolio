Making document verification feel less like paperwork, and more like a guided conversation.

IDfy 360 explores a compact Aadhaar verification flow where users choose a document, understand why DigiLocker is recommended, and start verification without feeling pushed into a black box.

Here is the whole thing.

Aadhaar verification is a trust-heavy moment. The interface has to make the user feel oriented, tell them what is happening, and recommend the safest path without overwhelming them.

So the design turns the flow into three visible steps: choose the document, choose the method, then start verification.

01
Let’s Set The Context

Verification usually starts with a little anxiety.

Picture a user trying to complete onboarding for a financial, hiring, lending, or enterprise workflow. They are not thinking about APIs, OCR, KYC, or risk engines. They are thinking, “Will this work? Is this safe? How long will it take?”

That moment needs clarity. A vague verification screen can make users hesitate. A guided one can make the same process feel calm, predictable, and trustworthy.

02
The Problem Scenario

The user has choices, but choices can become friction.

The selected Figma frame starts with a simple decision: choose your document type. Aadhaar Card is visible inside a dropdown, which keeps the first step familiar and compact.

Then comes the bigger decision: how should the user verify? DigiLocker is recommended because it can securely fetch Aadhaar details without manual entry. Face Authentication remains available, but visually secondary.

Old mental model “Upload something, wait, and hope it passes.”
Better mental model “Pick Aadhaar, use the recommended secure route, and continue.”
Design job Reduce uncertainty before the user clicks Start Verification.
Problem Statement

How might we make identity verification feel guided, secure, and easy to complete without hiding important decisions?

03
Project Goals

Three goals shaped the flow.

The screen is intentionally compact. It does not try to teach the entire verification ecosystem. It gives just enough structure for the user to move forward with confidence.

01

Make the next step obvious

Numbered sections help users know where they are in the flow.

02

Recommend without forcing

DigiLocker gets a stronger visual treatment, but Face Authentication remains available.

03

Keep trust visible

Helper copy explains that Aadhaar details are fetched securely with no manual entry.

UI Breakdown

Header

Aadhaar Card is shown inside a bordered dropdown, making the selected state explicit and editable.

Step 2

Choose method

The DigiLocker card opens by default, with an active blue border and “Recommended” badge.

Footer

Completion state

“Complete all steps to continue” keeps the task status visible and avoids premature completion.

Sketching The Logic

Before polish, the flow is just a hierarchy problem.

The screen needs to answer four questions in order: what am I doing, what document is selected, what method should I use, and what happens next?

Final Frame

A compact, friendly verification card.

The final UI uses calm spacing, familiar dropdown and card patterns, and a strong primary CTA. The result feels closer to being guided by a product than being processed by a system.

Reflection

Small flows carry a lot of trust.

Identity verification is rarely the user’s goal. It is the gate they need to pass through to get to the product. A good verification flow respects that: it is clear, short, secure-feeling, and emotionally lightweight.
